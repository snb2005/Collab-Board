One architectural improvement I'd strongly recommend
Introduce a Repository layer between your services and MongoDB. Instead of WorkspaceService calling MongoDB directly, have it call WorkspaceRepository. The repository encapsulates all database operations.
For example:
WorkspaceController
        ↓
WorkspaceService
        ↓
WorkspaceRepository
        ↓
MongoDB

This has several advantages:
Services remain focused on business logic rather than database queries.
Swapping MongoDB for another database in the future becomes much easier.
Unit testing is simpler because repositories can be mocked.
The overall design aligns with common enterprise architectures, which is a good discussion point in interviews.
